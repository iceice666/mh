# mh — Minimal PTC Agent Harness Specification

**Status:** Draft
**Target:** v0.1
**Project name:** `mh`
**Primary implementation language:** Rust
**PTC runtime:** MicroQuickJS

---

## 1. Overview

`mh` 是一個小型、opinionated、以 **Programmatic Tool Calling (PTC)** 為核心 execution model 的 agent harness。

`mh` 不試圖成為通用 agent framework，也不以 plugin ecosystem、第三方 extension compatibility 或 graphical workflow 為設計目標。

核心思想是：

> **PTC is the shell language. Tools are syscalls. MicroQuickJS is userspace. mh is the runtime.**

模型不需要透過大量：

```text
model
→ tool
→ model
→ tool
→ model
```

round trip 完成 procedural work。

模型可以生成一段受限 JavaScript，由 `mh` 在 MicroQuickJS VM 中執行，並在單次 PTC execution 中：

* 搜尋 repository
* 讀取多個檔案
* 執行 command
* 過濾 tool output
* 聚合資訊
* 修改檔案
* 驗證結果

最後只將必要結果返回 model context。

---

# 2. Goals

`mh` 的主要目標：

1. **PTC-first execution**
2. **低 context pollution**
3. **低 inference round-trip 數量**
4. **可控且 deterministic 的 tool ABI**
5. **隔離模型生成程式與 host OS**
6. **支援不同 model/provider 的 tool/PTC dialect**
7. **可靠的 session persistence 與 recovery**
8. **適合 coding agent 長任務**
9. **實作簡單，可直接 fork 修改**
10. **避免為第三方 extensibility 付 abstraction cost**

---

# 3. Non-Goals

v0.x 不以以下能力為目標：

* Generic plugin API
* Stable third-party extension ABI
* MCP compatibility as core architecture
* GUI
* Browser automation
* Generic RAG system
* Vector database
* Automatic agent swarm
* Built-in project management
* GitHub workflow orchestration
* Marketplace
* Node.js compatibility
* Full ECMAScript compatibility
* Arbitrary JavaScript package execution

如果需要這些功能，優先直接修改或 fork `mh`。

# 4. Design Principles

## 4.1 PTC-first

Tool call 不應是特殊 execution path。

所有 executable model actions 最終應盡量 lowering 成 canonical PTC execution。

例如 native function call：

```json
{
  "name": "read",
  "arguments": {
    "path": "src/main.rs"
  }
}
```

內部可被 lowering 為：

```js
return tool("read", {
    path: "src/main.rs"
});
```

因此：

```text
Native Function Calling
        │
        ▼
      Lowering
        │
        ▼
Canonical PTC
        │
        ▼
MicroQuickJS
```

`mh` 應盡可能只有一套 execution semantics。

---

## 4.2 Small trusted core

核心 runtime 必須保持小。

主要 trusted components：

```text
Model adapter
Context compiler
PTC runtime
Tool dispatcher
Capability enforcement
Session store
```

其他功能不是 kernel responsibility。

---

## 4.3 Host-controlled semantics

JavaScript 不直接擁有 OS capability。

禁止直接提供：

```text
fs
process
child_process
fetch
require
import
```

所有 side effect 必須經過 `mh` tool ABI。

---

## 4.4 Tool output is not context

Tool output 與 model context 必須視為不同 storage domain。

例如：

```text
cargo test
   │
   ├── 4 MB stdout
   └── 500 KB stderr
          │
          ▼
     Result Store
          │
       handle #42
          │
          ▼
      PTC program
          │
     filter / grep
          │
          ▼
      1 KB result
          │
          ▼
        Model
```

Large output 不應預設注入 context。

---

## 4.5 Opinionated over generic

若：

```rust
match tool {
    Tool::Read => ...
    Tool::Exec => ...
}
```

比一套 plugin registry 更簡單，就使用前者。

內部 API 不承諾 stability。

# 6. Agent Loop

核心 agent loop 應保持簡單。

概念：

```rust
loop {
    let context = context_compiler.compile(session)?;

    let response = model.generate(context)?;

    match normalize(response)? {
        Action::Text(text) => {
            session.append(text);

            if response.is_final() {
                break;
            }
        }

        Action::Program(program) => {
            let result = ptc.execute(program)?;
            session.append_ptc_result(result);
        }
    }
}
```

Agent loop 本身不應實作：

* file handling
* shell handling
* git logic
* planning system
* test logic

這些屬於 tool/runtime layer。

# 7. Canonical PTC

## 7.1 Language

Canonical PTC 使用 MicroQuickJS 可執行的受限 JavaScript dialect。

推薦僅依賴：

```text
var
function
return

if / else
switch

for
while

Array
Object

String
Number
Boolean

JSON

try / catch
```

第一版不依賴：

```text
let
const

async
await
Promise

class

import
export

require

Proxy

generator

dynamic module loading
```

是否允許額外 ECMAScript feature 由實際 MicroQuickJS compatibility 決定，但 canonical model prompt 不應要求它們。

---

# 8. PTC ABI

PTC runtime 提供少量 global primitives。

最基本：

```js
tool(name, args)
```

例如：

```js
var files = tool("glob", {
    pattern: "src/**/*.rs"
});

return files;
```

---

## 8.1 Convenience globals

為降低模型生成成本，可以提供：

```js
read(path)
write(path, content)
edit(args)
glob(pattern)
grep(args)
exec(command)
```

但 canonical semantics 必須等價於：

```js
tool(...)
```

例如：

```js
read("src/main.rs")
```

等價：

```js
tool("read", {
    path: "src/main.rs"
});
```

---

# 9. Core Tool Set

v0.1 至少提供以下 tool。

## 9.1 `read`

```js
read("src/main.rs");
```

或：

```js
tool("read", {
    path: "src/main.rs",
    offset: 0,
    limit: 10000
});
```

功能：

* read text
* bounded output
* optional byte/line ranges

---

## 9.2 `write`

```js
write("src/foo.rs", content);
```

完整覆寫檔案。

必須經 filesystem capability check。

---

## 9.3 `edit`

應支援 deterministic edit。

推薦：

```js
edit({
    path: "src/main.rs",
    old: "...",
    new: "..."
});
```

第一版不需要實作 complex AST editing。

---

## 9.4 `glob`

```js
glob("src/**/*.rs");
```

---

## 9.5 `grep`

```js
grep({
    pattern: "unsafe",
    paths: ["src"]
});
```

應盡可能由 host implementation 執行，不要求 VM 自己掃描所有檔案。

---

## 9.6 `exec`

```js
var result = exec({
    command: ["cargo", "test"],
    timeout_ms: 120000
});
```

禁止預設：

```js
exec("arbitrary shell string");
```

推薦 argv-based API：

```text
program + argv
```

Shell interpretation 必須是 explicit option。

---

## 9.7 Git

第一版可以直接由 `exec(["git", ...])` 實作。

之後視需求增加：

```text
git_status
git_diff
git_log
```

如果 dedicated primitive 能明顯降低 context/tool output 才新增。

---

# 10. ToolResult

Large tool result 不應直接轉為 JavaScript object/string。

應支援 host-backed handle。

概念：

```rust
struct ToolResult {
    id: ResultId,
    metadata: ResultMetadata,
}
```

PTC 中：

```js
var result = exec({
    command: ["cargo", "test"]
});

return {
    exitCode: result.exitCode,
    errors: result.stdout.grep("error"),
    stderr: result.stderr.tail(50)
};
```

其中：

```text
result.stdout
result.stderr
```

可以是 host object / opaque handle。

---

# 11. Result Store

Result Store 儲存：

* stdout
* stderr
* large file contents
* structured tool results
* temporary blobs

Result 必須可以：

```text
read range
tail
head
grep
match
JSON parse
length query
```

不需要將完整內容 materialize 到 JS heap。

---

## 11.1 Lifetime

結果至少區分：

```text
Execution-local
Turn-local
Session-local
Persistent
```

v0.1 可先只實作：

```text
execution
session
```

---

# 12. Batch Operations

PTC 的核心目的是減少 inference/tool round trip，因此 batch operations 是 first-class capability。

例如：

```js
var files = glob("src/**/*.rs");

var results = batch("read", files.map(function(path) {
    return {
        path: path
    };
}));

return results;
```

若 MicroQuickJS dialect 或 implementation 不適合 `.map()`，模型 prompt 應偏好 explicit loops。

---

# 13. Parallel Execution

Parallelism 由 host runtime 控制，不依賴 JS Promise。

推薦 API：

```js
var results = batch("read", [
    { path: "src/a.rs" },
    { path: "src/b.rs" },
    { path: "src/c.rs" }
]);
```

其中 `batch()` 可平行執行 compatible tools。

第一版不一定需要：

```text
spawn()
join()
future
promise
```

`batch` 足以涵蓋多數 repository inspection workload。

---

# 14. Resource Budget

每次 PTC execution 必須有限制。

例如：

```rust
struct PtcBudget {
    wall_time_ms: u64,
    instruction_limit: Option<u64>,
    memory_bytes: usize,

    max_tool_calls: usize,
    max_processes: usize,

    max_result_bytes: usize,
}
```

應防止：

```js
while (true) {}
```

以及：

```js
while (true) {
    exec(["cargo", "build"]);
}
```

---

# 15. Cancellation

每個 model request、PTC execution 與 tool execution 都必須可被取消。

最低需求：

```text
Ctrl-C
   │
   ▼
cancel current operation
   │
   ├─ terminate child processes
   ├─ interrupt VM
   └─ preserve session state
```

Cancellation 不應導致 session corruption。

---

# 16. Capability Model

MicroQuickJS 本身不能直接取得 OS resource。

PTC execution 只能經由 tool ABI。

Capability 可簡化為：

```rust
struct Capabilities {
    fs_read: Vec<PathRule>,
    fs_write: Vec<PathRule>,

    exec: ExecPolicy,

    network: NetworkPolicy,
}
```

第一版甚至可以只支援：

```text
workspace read
workspace write
exec
```

---

## 16.1 Default policy

預設：

```text
filesystem:
  read: workspace/**
  write: workspace/**

exec:
  cwd: workspace

network:
  disabled
```

Network access 可以之後增加。

---

# 17. Model Adapter

Provider adapter 不應知道 tool implementation。

統一輸出：

```rust
enum ModelOutput {
    Text(String),

    Program {
        language: ProgramLanguage,
        source: String,
    },

    FunctionCall {
        name: String,
        arguments: Value,
    },
}
```

# 18. Compatibility Layer

不同模型/provider 可能輸出不同形態：

```text
native function call

JavaScript PTC

tools.read(...)

call_tool(...)

XML-ish tool blocks

custom code fences
```

`mh` 將其 normalize 成：

```text
canonical PTC
```

---

## 18.1 Runtime alias first

如果 compatibility 可以透過 global alias 解決，就不要 source rewrite。

例如同時 expose：

```js
tool(...)
call_tool(...)

tools.read(...)
tools.exec(...)
```

其底層全部呼叫同一個 host dispatcher。

---

## 18.2 Source transformation

只有 syntax incompatibility 才進行 source transform，例如：

```text
const
let
arrow functions
async/await
```

v0.1 可以完全不提供 transpiler。

若 parse failure，優先：

```text
PTC parse error
      │
      ▼
send concise diagnostic to model
      │
      ▼
model repairs program
```

# 19. Context Compiler

Session history 與 model context 必須分離。

```text
Session
   │
   ▼
Context Compiler
   │
   ├── system instructions
   ├── task
   ├── recent messages
   ├── selected tool/PTC results
   ├── relevant files
   └── compacted history
   │
   ▼
Model Context
```

---

## 19.1 Context item

概念：

```rust
struct ContextItem {
    source: ContextSource,
    priority: Priority,
    estimated_tokens: usize,
    content: Content,
}
```

---

## 19.2 Priorities

推薦：

```text
Hard
Sticky
Working
Ephemeral
```

例如：

```text
system constraints    Hard
user task             Hard
current code          Working
old compiler output   Ephemeral
previous decisions    Sticky
```

---

# 20. Compaction

Compaction 應針對 information source，而不是直接 summarize 整段 conversation。

例如：

```text
compiler output
      ↓
diagnostics summary
```

```text
repository exploration
      ↓
relevant paths + findings
```

```text
completed implementation
      ↓
changes + remaining work
```

v0.1 可以先使用簡單 whole-session summary，但資料模型不應假設 conversation history 永遠等於 prompt history。

---

# 21. Session Model

Session 必須 durable。

推薦 append-only event log。

事件例如：

```text
UserMessage
AssistantMessage

ModelStarted
ModelCompleted

PtcStarted
PtcCompleted
PtcFailed

ToolStarted
ToolCompleted
ToolFailed

FileChanged

Compacted

Interrupted
```

## 21.1 Recovery

Crash 後：

```text
mh resume
```

至少應恢復：

* conversation
* task state
* result metadata
* last safe operation boundary

未完成 child process 不要求恢復。

# 22. Storage

v0.1 可以採：

```text
.mh/
├── session.jsonl
├── state.json
└── blobs/
```

例如：

```text
.mh/blobs/<hash>
```

不強制 SQLite。

若之後需要：

* indexing

* random access

再考慮 SQLite。

# 23. Verification

v0.1 不需要完整 autonomous verifier，但 harness 應支援 verification workflow。

例如模型產生：

```js
var test = exec({
    command: ["cargo", "test"]
});

if (test.exitCode !== 0) {
    return {
        success: false,
        errors: test.stderr.tail(100)
    };
}

return {
    success: true
};
```

後續可加入：

```text
claim
evidence
verification
```

資料模型。

# 24. Steering

長任務應允許使用者中途輸入。

狀態：

```text
running model
running PTC
running tool
idle
```

使用者新訊息可：

```text
queue
interrupt
cancel
```

v0.1 最低支援：

```text
cancel current execution
enqueue next user instruction
```

# 25. Subagents

Subagent 不是 v0.1 requirement。

PTC 本身應先解決：

* repository-wide search
* batch read
* batch execution
* filtering
* aggregation

只有在需要：

* independent reasoning context
* parallel reasoning
* review isolation

時才需要 subagent。

未來若實作，應共用：

```text
Tool ABI
PTC runtime
Session store
Context compiler
```

而不是建立第二套 harness。

# 26. RPC / Frontend Boundary

Core runtime 不應和 TUI 綁死。

最低可以有：

```text

```

或 internal Rust API。

概念：

```text

  │
  ├── send_message
  ├── cancel
  ├── resume
  └── inspect_session
```

RPC 可以延至 v0.2。

# 33. Core Invariants

以下 invariants 應盡量保持：

### I. Model code never directly owns OS access

```text
Model
  ↓
PTC
  ↓
Tool ABI
  ↓
Host
```

---

### II. Large tool output never automatically enters context

```text
Tool output != model context
```

---

### III. PTC VM is disposable

任何 execution 都可以被：

```text
terminate
discard
restart
```

不依賴 VM 中的 durable state。

---

### IV. Session state survives VM death

Durability 屬於 host，不屬於 JavaScript runtime。

---

### V. Native FC and PTC share execution semantics

避免兩套 permission、logging、result handling、error semantics。

---

### VI. Compatibility belongs at the boundary

Provider quirks 不應污染 tool implementation。

---

# 34. Example Interaction

User：

```text
找出這個 Rust project 裡所有可能 panic 的 unwrap，
但 tests 不用管，告訴我哪些值得修。
```

Model 生成：

```js
var files = glob("src/**/*.rs");
var findings = [];

for (var i = 0; i < files.length; i++) {
    var matches = grep({
        path: files[i],
        pattern: ".unwrap()"
    });

    if (matches.length > 0) {
        findings.push({
            path: files[i],
            matches: matches
        });
    }
}

return findings;
```

`mh` 執行 PTC。

如果 repository 很大，中間：

```text
50 files
300 KB source
120 grep matches
```

不需要全部進 model context。

模型只拿到整理後 findings，再判斷哪些 unwrap 值得處理。

---

# 35. Example Coding Task

User：

```text
修掉目前 failing tests。
```

模型：

```js
var test = exec({
    command: ["cargo", "test"]
});

return {
    exitCode: test.exitCode,
    failures: test.stdout.grep("FAILED"),
    errors: test.stderr.grep("error")
};
```

第二次 inference 後模型定位問題並 edit。

最後：

```js
var test = exec({
    command: ["cargo", "test"]
});

var diff = exec({
    command: ["git", "diff", "--stat"]
});

return {
    success: test.exitCode === 0,
    testTail: test.stdout.tail(20),
    changes: diff.stdout.read()
};
```

Harness 最終只需要把這些 evidence 放回 model。

# 36. Success Criteria

`mh` 成功並不由 feature count 衡量。

成功標準是：

### Fewer inference turns

同樣 repository exploration workload，需要更少：

```text
model ↔ tool
```

round trips。

### Lower context consumption

大量 tool output 不直接消耗 token budget。

### Predictable execution

模型生成的 procedural work 由可限制、可取消的 VM 執行。

### Small implementation

核心架構能由少量 Rust module 理解，而不需要 framework-level indirection。

### Easy personal modification

想新增能力時：

```text
找到 tool/runtime code
→ 修改
→ build
```

而不是理解 plugin lifecycle。

---

# 37. One-Sentence Definition

> **mh is a small, opinionated PTC-first agent harness that runs model-generated procedural tool programs inside a sandboxed MicroQuickJS runtime.**
